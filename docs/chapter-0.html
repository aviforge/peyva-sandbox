Chapter 0

What Are We Building?

A peer-to-peer wallet, built one honest layer at a time.

Foundations Beginner 15 min

1. Intuition

  • Alice opens her wallet, picks Bob, types $20, and hits send. Seconds later, Bob has it.
  • That's the whole system, from the outside.
  • Every chapter answers one question about that moment: how the request arrives, what the program does with it, what could go wrong.

2. Concepts

  • User. A person with an identity in the system. Owns exactly one account.
  • Account. One owner and an amount, the thing this book protects.
  • Balance. How much an account holds. Must never go negative, be lost, or be double-spent.
  • Vault. The component holding every account and what's in it. Nothing else is allowed to change a balance.
  • Transfer. A request to move money between accounts, the core action of this book.
  • History. The record of every transfer. If the balance is the answer, history is the proof.

3. Under the Hood

  • Today: one process, one account, one hardcoded balance, printed to the screen.
  • No Gateway, Teller, Ledger, or Courier yet. Those arrive only once a real problem needs them.
  • A system earns its structure one real problem at a time.

4. Build It Hands-on

  • Build the Vault: the first component, in its smallest useful form.

Zero-shot prompting. No examples, no reasoning scaffold, no role: just the instruction. The task has one obvious shape, so scaffolding would cost tokens and buy nothing. Every technique after this is a departure from this baseline, which is why it comes first.

Documented in The Prompt Report: Zero-Shot

Build the Vault. The component that holds accounts and what's in them. Nothing else is allowed to change a balance.

An account is an owner and an amount. Seed it with one account, alice, holding 100. Print the Vault's contents on startup, run until interrupted, then print a shutdown message.

One file, standard library only. No persistence, no network. The Vault earns structure later, when a real problem demands it.

Done when running it prints alice's balance and it exits cleanly on Ctrl+C.

5. Break It Test it

  • This is the simplest way a system can fail: turn it off.
  • Run it with `go run .`. Confirm it prints the account's starting balance.
  • Stop it with Ctrl+C, run it again. The balance resets to the hardcoded value.
  • Nothing survived: expected today, and exactly the problem Chapter 5 (Storing Money) solves.

Quick tip: Every system starts as one honest process. Resist the urge to design for scale you don't have yet.
